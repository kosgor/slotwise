# 0005. Анимации: CSS для прокрутки, Framer Motion — только для состояния

Дата: 2026-10-16 · Статус: принято

## Коротко

Анимации сами по себе не тормозят сайт — тормозит JavaScript, который нужен, чтобы их запустить.
Библиотека Framer Motion весит ~25 КБ, и телефон должен её скачать и выполнить до того, как страница
станет отзывчивой. Плавное появление блоков при прокрутке браузер теперь умеет делать сам, через CSS,
без единой строки JS. Поэтому: простое и декоративное — на CSS, сложное и зависящее от действий
пользователя (смена цены в тарифах) — на Framer Motion, и только на той странице, где оно есть.
Решение принято по замерам, а не на глаз: одна «рекомендованная» оптимизация на деле всё замедлила.

## Контекст

План: «Framer Motion: появление секций при скролле, переходы страниц, интерактив в тарифах,
микро-анимации» и одновременно «Lighthouse 95+ на мобильном, минимум клиентского JS».
Замеры Lighthouse (mobile, медиана из 3 прогонов) показали, что эти цели конфликтуют.

## Что измерили

| Вариант                                                               | Главная, Performance | TBT        |
| --------------------------------------------------------------------- | -------------------- | ---------- |
| `motion` целиком на всех страницах (один прогон, до остальных правок) | 89                   | 190 мс     |
| `LazyMotion` с **асинхронной** загрузкой функций                      | 82                   | 300+ мс    |
| `LazyMotion` с синхронной загрузкой                                   | 88                   | 186 мс     |
| + мобильное меню грузится по клику                                    | 89                   | 164 мс     |
| **Появление при скролле на CSS, Motion только в тарифах**             | **90**               | **184 мс** |

Асинхронная загрузка, которую рекомендуют как оптимизацию, здесь **ухудшила** результат: догрузка
функций вызывает отдельный долгий рендер всех анимированных блоков. Без замера мы бы её оставили.

## Решение

- **Появление при прокрутке** — CSS scroll-driven animations (`animation-timeline: view()`), класс
  `.reveal` в `app/globals.css`. Ноль JavaScript. Работает как прогрессивное улучшение: без поддержки
  в браузере, при `prefers-reduced-motion` и без JS контент просто виден сразу.
- **Framer Motion** (`LazyMotion` + компоненты `m`) — только там, где анимация зависит от состояния:
  смена цены в переключателе тарифов. Провайдер подключён внутри этого компонента, остальные страницы
  библиотеку не загружают.
- **Переход между страницами** — Web Animations API (`element.animate`), без библиотеки. Первый показ
  страницы не анимируется, чтобы не задерживать LCP.
- **Микро-анимации** (hover, нажатие) — CSS-переходы Tailwind с вариантом `motion-safe:`.

## Почему

- Анимация при прокрутке декоративна — она не должна стоить килобайт JS на каждой странице.
- Framer Motion оправдан там, где CSS неудобен: анимация появления/исчезновения по состоянию
  (`AnimatePresence`), жесты, layout-анимации. Это пригодится в чате (этап 4).

## Компромиссы

- Scroll-driven animations ещё не везде: Firefox показывает контент без анимации. Это приемлемо.
- Отклонение от буквы плана — зафиксировано здесь.

## Пересмотреть, когда

Понадобятся сложные анимации при прокрутке (параллакс, связанные последовательности) — тогда
`useScroll` из Motion точечно на конкретной странице.
