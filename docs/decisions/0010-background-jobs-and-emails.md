# 0010. Фоновые задачи (Inngest) и письма (React Email + Resend)

Дата: 2026-10-20 · Статус: принято

## Коротко

Всё, что может быть медленным или упасть, — письма, напоминания, возвраты, истечение удержаний —
выполняется в Inngest, а не в запросе пользователя или в вебхуке. Каждый шаг повторяется отдельно,
а успешный шаг не повторяется.

## Почему Inngest

| Вариант                         | Минус                                                                                        |
| ------------------------------- | -------------------------------------------------------------------------------------------- |
| Отправлять письмо в запросе     | Resend тормозит или падает — тормозит или падает бронь                                       |
| `setTimeout` / очередь в памяти | На serverless процесс живёт, пока идёт запрос; напоминание через 3 дня так не сделать        |
| Vercel Cron + таблица задач     | Свои ретраи, блокировки, «что уже отправлено» — это и есть Inngest, только самописный        |
| **Inngest**                     | Бесплатный тариф, `step.sleepUntil` для напоминаний, отмена по событию, локальный Dev Server |

## Задачи

| Задача                  | Запуск                           | Что делает                                                                                                     |
| ----------------------- | -------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `booking-confirmed`     | `booking/confirmed`              | Письмо клиенту и специалисту → спит до «за 24 часа» → напоминание. **Отменяется** событием `booking/cancelled` |
| `booking-cancelled`     | `booking/cancelled`              | Письмо клиенту (с суммой возврата) и специалисту                                                               |
| `booking-refunded`      | `booking/refunded` (вебхук)      | Письмо «возврат выполнен»                                                                                      |
| `booking-refund-needed` | `booking/refund-needed` (вебхук) | Возврат денег за бронь, которую нельзя сохранить, + письмо с объяснением                                       |
| `expire-unpaid-holds`   | cron `*/5 * * * *`               | Просроченные удержания → `expired`, закрыть их Checkout; повторить невыполненные возвраты                      |

## Защита от двойных писем

1. id события Inngest строится из id брони или события Stripe — повторная отправка отбрасывается.
2. Шаги `step.run` запоминают результат: падение шага «письмо специалисту» не отправит повторно
   письмо клиенту.
3. У каждого письма ключ идемпотентности Resend (`confirmed-client:<id>`).
4. Ошибка 4xx от Resend (неверный адрес, неподтверждённый домен) — `NonRetriableError`: повтор не
   поможет, ошибка остаётся видна в Inngest.

## Письма

- Шаблоны — React Email (`emails/`), предпросмотр: `npm run email:dev` (порт 3200).
- Доступность: `lang`, настоящий `<h1>`, текст читается без картинок, ссылки — настоящие ссылки,
  нет принудительного фона под текстом (тёмная тема почтовика инвертирует цвета), есть текстовая
  версия письма.
- Время — в поясе специалиста с названием пояса («Warsaw time»), а не просто числом.

## Локальная разработка

- Без `RESEND_API_KEY` письма пишутся в консоль сервера.
- Resend без своего домена доставляет только на адрес владельца аккаунта: `EMAIL_DEV_TO`
  перенаправляет все письма туда, настоящий получатель — в теме.
- Inngest Dev Server: `npm run jobs:dev` (UI на http://localhost:8288), `INNGEST_DEV=1` в `.env.local`.

## Последствия

- Если Inngest недоступен, действие пользователя всё равно проходит (`lib/jobs.ts` — best effort).
  Потерянное письмо не критично, потерянный возврат подберёт задача раз в 5 минут.
- Вебхук, наоборот, отвечает 500, если не удалось отправить событие: Stripe повторит.
- Письма подтверждения входа от Supabase Auth пока идут через встроенную почту Supabase (только
  участникам проекта). SMTP через Resend требует своего домена — при деплое.
