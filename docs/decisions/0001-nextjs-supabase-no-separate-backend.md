# 0001. Next.js + Supabase вместо отдельного бэкенда

Дата: 2026-10-15 · Статус: принято

## Контекст

Slotwise нужны страницы, серверные мутации, авторизация, Postgres, хранилище файлов,
векторный поиск и эндпоинты для вебхуков. Это пет-проект одного разработчика на бесплатных тарифах.

## Решение

Один Next.js-проект (App Router) содержит UI, Server Actions и API-маршруты.
Supabase даёт Postgres, Auth, Storage и pgvector. Без Express/NestJS, Prisma, Redis и Docker.

## Почему

- Одна цель деплоя (Vercel), один репозиторий, один язык. Меньше связующего кода, в котором можно ошибиться.
- Изоляция данных обеспечивается в самой базе через RLS, а не только в коде приложения.
  Если в Server Action забыли проверку прав, данные всё равно не утекут.
- Supabase закрывает то, ради чего здесь писали бы свой бэкенд: авторизацию, файлы, миграции, векторы.

## Компромиссы

- Привязка к возможностям Supabase (RLS с `auth.uid()`, Storage). Переезд потребует усилий.
- Долгие задачи нельзя выполнять в serverless-функциях — они уходят в Inngest.
- Бесплатный проект Supabase засыпает после недели без активности — перед показом демо его надо разбудить.

## Пересмотреть, когда

Вакансия явно требует отдельный Node-бэкенд, или нагрузка перерастёт ограничения serverless.
