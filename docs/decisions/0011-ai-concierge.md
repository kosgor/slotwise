# 0011. AI-консьерж: права, подтверждения, RAG и лимиты

Дата: 2026-10-24 · Статус: принято

## Коротко

Чат (`/api/chat`) работает **от имени вошедшего пользователя**: инструменты ходят в Supabase с его
сессией, поэтому RLS и функции бронирования решают, что модель может увидеть и изменить. Модель ничего
не записывает сама: бронь подтверждает человек кнопкой, отмену — одобрением в чате. История лежит в
базе, сервер не доверяет истории из браузера. Каждый запрос к модели учитывается и ограничивается в
базе одной функцией.

## Провайдер и SDK

Vercel AI SDK 7 + Gemini (`@ai-sdk/google`): бесплатный тариф для разработки, и чат, и embeddings у
одного провайдера. Модель — `gemini-3.5-flash-lite` (дешёвая, умеет вызывать инструменты), embeddings —
`gemini-embedding-2`, урезанные до 768 измерений. Смена провайдера — только `lib/ai/models.ts`.

## Права: почему не service role

| Вариант                                          | Что будет при prompt injection                                       |
| ------------------------------------------------ | -------------------------------------------------------------------- |
| Инструменты на секретном ключе + проверки в коде | Одна забытая проверка — и «покажи все брони» возвращает чужие данные |
| **Инструменты с сессией пользователя**           | Модель видит ровно то, что пользователь видит кликами. Обойти нечем  |

`getMyBookings` дополнительно фильтрует `client_id` — это смысл («мои записи как клиента»), а не защита.

## Записи только руками человека

- **`proposeBooking`** ничего не пишет: перепроверяет слот по живой доступности и возвращает
  предложение. Кнопка «Confirm» в карточке вызывает тот же `bookSlot`, что и страница записи, —
  цена и расписание проверяются в `book_slot()`, оплата идёт через Stripe Checkout.
- **`cancelBooking`** выполняется только после одобрения (`toolApproval: 'user-approval'`). Текст,
  который человек одобряет («Cancel Yoga with Anna on Tuesday, 10:00?»), строится **на сервере из
  базы**, а не из слов модели. Чужая или уже отменённая бронь отклоняется автоматически.
- Одобрения подписываются HMAC (`experimental_toolApprovalSecret`, `TOOL_APPROVAL_SECRET`).

## История: браузер присылает только новое

Клиент отправляет одно последнее сообщение (`prepareSendMessagesRequest`). Сервер берёт историю из
`messages` (RLS: только свои беседы) и принимает из запроса ровно две вещи (`lib/ai/chat-messages.ts`):
новый текст пользователя (только текст, до 1000 символов) или ответ «да/нет» на ожидающее
подтверждение. Подделать «результат инструмента» или «ответ ассистента» нельзя — они не принимаются.

Сообщения хранятся в формате AI SDK `UIMessage`: колонка `parts` (jsonb) вместо пары
`content` + `tool_calls` из плана — так карточки инструментов восстанавливаются после перезагрузки
ровно такими, какими их видел пользователь. При загрузке история проверяется против текущих схем
инструментов (`safeValidateUIMessages`); несовместимая старая история не ломает чат.

## RAG

- Специалист загружает `.txt`/`.md` (до 200 КБ, до 5 документов — триггер в базе) в приватный бакет
  `provider-documents`, путь начинается с `provider_id` — так политики Storage проверяют владельца.
- Inngest `process-document`: текст → чанки ~800 символов с перекрытием 150 по абзацам и предложениям
  (`lib/ai/chunking.ts`) → embeddings → `replace_document_chunks()` (старые чанки заменяются в одной
  транзакции, повтор задачи не дублирует). Embeddings не проходят через состояние Inngest.
- Поиск — `match_document_chunks()`: только чанки одного специалиста, только `ready`-документы
  одобренного профиля (или свои), только выше порога сходства 0.6. «Ничего похожего» — пустой
  результат, и модель отвечает «не знаю», а не пересказывает ближайший шум.
- Точный поиск без HNSW: на сотнях чанков одного специалиста он быстрый и всегда точный.
- Ответы о правилах специалиста называют документ-источник; под ответом в UI — «Sources: …».

## Лимиты и стоимость

`claim_ai_request()` атомарно (advisory lock на пользователя) проверяет 6 запросов в минуту и дневной
лимит (Free 30, Pro 150 — Pro у специалиста с активной подпиской) и вставляет строку `ai_usage`.
Отказ — до вызова модели, он ничего не стоит. Токены и стоимость дописывает сервер после ответа.
Пользователь читает свою статистику, но писать в `ai_usage` не может — иначе обнулил бы себе цифры.
Стоимость — в микродолларах (`cost_micros`): ответ стоит доли цента, целые центы округлили бы всё в 0.
На бесплатном тарифе реальный счёт $0, в `ai_usage` пишется цена того же трафика на платном.

Ещё: история в промпте — последние 20 сообщений, ответ — до 800 токенов, до 5 шагов инструментов;
«Стоп» прерывает запрос к модели (`abortSignal`), недочитанный ответ не оплачивается.

## Structured output

Черновик профиля и недельная сводка — `generateText` + `Output.object(zod)`. Черновик ничего не
сохраняет: заполняет поля формы, человек проверяет и жмёт Save. В сводке **все числа считает код**
(`lib/ai/weekly-stats.ts`), модель только формулирует.

## Компромиссы

- PDF не поддерживается — только текст. Извлечение текста из PDF — отдельная задача.
- Нет возобновления стрима после обрыва: вопрос сохранён, ответ можно запросить заново («Try again»).
- Ответы недетерминированы: качество проверяется вручную (`npm run evals`), не в CI.

## Пересмотреть, когда

- Чанков у специалиста станет тысячи → индекс HNSW.
- Понадобится платная модель → цены в `lib/ai/models.ts` и лимиты в `lib/ai/limits.ts` + миграция.
