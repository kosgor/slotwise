# 0002. shadcn/ui на примитивах Radix

Дата: 2026-10-15 · Статус: принято

## Контекст

Компонент shadcn состоит из двух слоёв:

1. **Примитив (поведение, невидимый слой)** — управление с клавиатуры, фокус, `aria`-атрибуты, закрытие по Esc,
   ловушка фокуса в модальном окне, позиционирование выпадающих списков. Это самая сложная часть,
   её берут из готовой headless-библиотеки (без собственных стилей).
2. **Стиль (внешний вид)** — Tailwind-классы: размеры, отступы, радиусы, шрифты, иконки.

shadcn называет конфигурацию «`<библиотека примитивов>-<визуальный пресет>`»:

- `base-nova` — примитивы **Base UI** + пресет **Nova**
- `radix-nova` — примитивы **Radix UI** + пресет **Nova**

Пресет Nova (иконки Lucide, шрифт Geist) одинаков в обоих вариантах, поэтому выглядят они одинаково.
Разница — в том, какая библиотека отвечает за поведение под капотом и какой у компонентов API
(например, `asChild` у Radix).

Текущая версия shadcn CLI по умолчанию выбирает `base-nova`.

## Решение

Используем `radix-nova`: пакет `radix-ui`, инициализация через `shadcn init --base radix`.

## Почему

- Radix — исходная основа shadcn: на нём написано большинство существующих проектов, примеров и ответов на вопросы.
- В вакансиях и чужих кодовых базах (takeover-проекты) почти всегда Radix — опыт переносится напрямую.
- Наш план изначально указывает shadcn/ui (Radix).

## Компромиссы

- Base UI новее (делают авторы Radix и MUI) и активно развивается. Если экосистема shadcn перейдёт на него,
  компоненты придётся переустановить: `shadcn init --base base --reinstall`.
- Смешивать две библиотеки в одном проекте нельзя: у них разный API.

## Пересмотреть, когда

Новые компоненты shadcn начнут выходить только для Base UI, или Radix перестанет поддерживаться.
