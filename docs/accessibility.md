# Доступность: аудит по WCAG 2.2 AA

Дата: 2026-10-25. Цель — WCAG 2.2 уровня AA. Ниже — что проверено, чем, и что известно как
ограничение. **Ручной проход скринридером (NVDA, VoiceOver) ещё не сделан** — это единственная проверка,
которую автотесты не заменяют; до неё аудит неполный.

Страницы под axe: главная, каталог (с фильтрами и пустым состоянием), профиль специалиста (с секцией

дашборд, отзывы, журнал).

## Чек-лист по принципам

### Воспринимаемость

- [x] 1.1.1 Альтернативный текст: фото специалистов с `alt`, декоративные иконки `aria-hidden`.
- [x] 1.3.1 Структура: ландмарки, один `h1`, заголовки по порядку, списки и таблицы семантичны.
      Таблицы админки — `<caption>`, `<th scope="col">` и `<th scope="row">`.
- [x] 1.3.5 `autocomplete` у полей входа и регистрации.
- [x] 1.4.1 Не только цвет: статусы (Badge) — текстом; ошибки — иконкой и текстом.
- [x] 1.4.3 / 1.4.11 Контраст текста ≥ 4.5:1, элементов интерфейса ≥ 3:1 в обеих темах.
- [x] 1.4.10 Reflow: 320 px без горизонтальной прокрутки (широкие таблицы — в прокручиваемом регионе
      с `tabindex="0"` и подписью).
- [x] 1.4.13 Подсказки при наведении на графиках дашборда дублируют данные, которые есть в таблице и в
      текстовой сводке; сами графики `aria-hidden`.

### Управляемость

- [x] 2.1.1 Клавиатура: всё доступно с клавиатуры, включая чат («Стоп», карточки, «Подтвердить»).
- [x] 2.1.2 Нет ловушек фокуса; Dialog/Sheet закрываются по Esc с возвратом фокуса.
- [x] 2.2.1 Регулируемое время: удержание слота можно продлить («I need more time»), объявления за 5 и
      за 1 минуту, а не каждую секунду.
- [x] 2.4.1 Skip link первым в Tab-порядке.
- [x] 2.4.3 Порядок фокуса: после замены кнопки результатом (предложение записи, отмена из чата, открытие
      консьержа) фокус переходит на появившийся текст, а не на `<body>`.
- [x] 2.4.7 Видимый фокус (`focus-visible`) на всех интерактивных элементах.
- [x] 2.5.8 Размер целей ≥ 24×24 px.

### Понятность

- [x] 3.1.1 `lang="en"` у документа.
- [x] 3.3.1 / 3.3.3 Ошибки форм — текстом у поля (`aria-invalid`, `aria-describedby`), с подсказкой.
- [x] 3.3.8 Доступная аутентификация: без капчи, пароль можно вставить.

### Надёжность

- [x] 4.1.2 Имя, роль, значение: кнопки с действием в имени («Confirm booking: Yoga with Anna, Tuesday…»,
      «Hide review by Hugo B.»), сортировка таблиц — `aria-sort` и ссылка «sort oldest first».
- [x] 4.1.3 Сообщения о статусе: результаты действий — `role="status"` / `role="alert"`; в чате лента
      `role="log"` с `aria-live="off"`, а готовый ответ объявляется целиком отдельным `role="status"` —
      потоковые токены не зачитываются по одному.

## Известные ограничения

1. **Скринридеры не проверены вручную** (NVDA на Windows, VoiceOver на iPhone). Нужен проход
   «найти → записаться → оплатить → отменить» и чата.
2. **Выбор слота:** занятые слоты не показываются вовсе, а не `disabled` с объяснением.
3. **Путь записи:** шаги на одной странице с нумерованными `legend`, фокус при переходе между шагами не
   переносится.
4. **Чат:** ответ ассистента — простой текст; ссылки в тексте модели не кликабельны (кликабельны в
   карточках). Подсказки времени и стоимости модели зависят от её ответа — проверяются evals.
5. **Графики дашборда:** подсказка показывается только при наведении мышью; с клавиатуры те же цифры
   доступны в таблице «Show as table».
6. **Письма:** проверены семантика и текстовая версия; в настоящих почтовых клиентах — после ключа Resend.
7. Автотесты покрывают только автоматически проверяемую часть WCAG; критерии вроде 1.3.3, 2.4.6
   (понятность формулировок), 3.2.x (предсказуемость) оценены при разработке, но не ревьюером.
